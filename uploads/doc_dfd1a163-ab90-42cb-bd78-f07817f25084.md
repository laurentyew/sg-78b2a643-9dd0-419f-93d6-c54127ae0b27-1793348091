# Moderator Rush: Technical Spec

Sep 29, 2026 · @Laurent

## 1. Overview

Build a 10-round browser game at `/tools/spot-the-spam-comment-quiz` where players moderate fake social comments and DMs, get a score and a rank, and join the Social Kirin waitlist to unlock a full breakdown.

**Instructions to the AI builder**

- Follow this spec literally. Where it is silent, pick the simplest option and record the choice in `DECISIONS.md`.
- Score on the server. The correct answer for a round must never reach the browser before the player has answered that round.
- No live LLM calls anywhere in v1. All content comes from the `comments` table.
- Do not build anything listed under Out of scope.

**In scope (v1):** 10-round game, per-round feedback, result page with rank, share card, email gate for the category breakdown, referral link, analytics events, SEO copy on the same page.

**Out of scope:** endless mode, public leaderboard, accounts or login, translations, admin UI (content is seeded from JSON), live AI moderation demo.

**Assumed stack:** Next.js (App Router) on Vercel with Supabase. If the Social Kirin site uses something else, keep sections 4, 5, 6 and 8 to 13 and adapt sections 2, 3 and 7.

## 2. Stack and architecture

Next.js on Vercel with Supabase Postgres, and every write goes through server route handlers, never straight from the browser.

| Layer | Choice | Notes |
| --- | --- | --- |
| Framework | Next.js App Router, TypeScript strict | Server component for SEO copy, client component for the game |
| Styling | Tailwind CSS | Mobile-first, 375px baseline |
| Database | Supabase Postgres | Service-role key used only in route handlers; RLS on with no public policies |
| Validation | zod | Every request body and every env var |
| Rate limiting | Upstash Redis (`@upstash/ratelimit`) | Limits in section 11 |
| Email | Resend | Confirmation and welcome emails only |
| Share image | `next/og` ImageResponse | 1200x630, cached |
| Analytics | PostHog behind `lib/track.ts` | Swappable; never send emails or names |
| Tests | Vitest | Scoring, round selection, API guards |

**Request flow**

1. Page loads. Intro copy is server-rendered; game code loads after first paint.
2. Player taps Start. `POST /api/game/start` creates a `plays` row and returns 10 rounds with no answers.
3. For each round the player picks Keep, Hide, Reply or Ban. `POST /api/game/answer` stores the answer and returns whether it was correct plus the reason.
4. After round 10, `POST /api/game/finish` computes score, time, rank and the per-type breakdown, and returns a share URL.
5. The result page shows score and rank. The category breakdown is locked.
6. Player submits an email through `POST /api/lead`. The server sets a signed cookie for that play, and `GET /api/game/[playId]/breakdown` now returns the breakdown.
7. A confirmation email goes out. The lead counts toward the waitlist and referrals only after they confirm.

## 4. Database schema

Four tables and one view, all in `supabase/migrations/0001_init.sql`. Row level security is on for every table with no public policies, so only the server (service role) can read or write.

```sql
create type comment_type as enum ('spam','scam_dm','troll','complaint','sarcasm','question');
create type mod_action as enum ('keep','hide','reply','ban');

create table comments (
  id uuid primary key default gen_random_uuid(),
  platform text not null check (platform in ('instagram','tiktok','facebook','x')),
  kind text not null check (kind in ('comment','dm')),
  type comment_type not null,
  author_handle text not null,
  body text not null,
  best_action mod_action not null,
  alt_action mod_action,
  reason text not null,
  is_trap boolean not null default false,
  difficulty smallint not null default 1 check (difficulty between 1 and 3),
  active boolean not null default true,
  created_at timestamptz not null default now()
);

create table plays (
  id uuid primary key default gen_random_uuid(),
  session_id text not null,
  round_ids uuid[] not null,
  started_at timestamptz not null default now(),
  finished_at timestamptz,
  score smallint,
  total_ms integer,
  rank_key text,
  utm jsonb,
  referrer text,
  ip_hash text
);

create table play_answers (
  play_id uuid references plays(id) on delete cascade,
  comment_id uuid references comments(id),
  action mod_action,            -- null = timed out
  ms integer not null,
  correct boolean not null,
  answered_at timestamptz not null default now(),
  primary key (play_id, comment_id)
);

create table leads (
  id uuid primary key default gen_random_uuid(),
  email text not null unique,
  first_name text,
  role text check (role in ('brand','agency','creator','other')),
  play_id uuid references plays(id),
  referral_code text not null unique,
  referred_by text,
  consent_at timestamptz not null,
  confirm_token text not null,
  confirmed_at timestamptz,
  created_at timestamptz not null default now()
);
create index on leads (referred_by);

alter table comments enable row level security;
alter table plays enable row level security;
alter table play_answers enable row level security;
alter table leads enable row level security;

-- feeds the weekly 'X% fell for...' posts
create view stats_by_type as
select c.type, count(*) as answers,
       round(100.0 * avg((not a.correct)::int), 1) as pct_wrong
from play_answers a join comments c on c.id = a.comment_id
group by c.type;
```

**Waitlist position** (computed on read, not stored): `queue_score = epoch(created_at) - 86400 * confirmed_referrals`. Position = number of confirmed leads with a lower score, plus one. Each confirmed referral therefore moves a lead up by one day of queue time. Keep the formula in one function so the owner can tune it.

## 5. API contracts

All routes are JSON, validated with zod, and return `{ error: string }` with a 4xx status on failure. Type notation below is TypeScript.

**POST /api/game/start**

```ts
req:  { sessionId: string /* uuid from client */, utm?: Record<string,string> }
res:  { playId: string,
        timeLimitMs: 6000,
        rounds: { id: string, platform: string, kind: 'comment'|'dm',
                  authorHandle: string, body: string }[] /* length 10 */ }
```

Round selection follows the composition rules in section 6. The response must not contain `best_action`, `alt_action`, `reason`, `type` or `is_trap`.

**POST /api/game/answer**

```ts
req:  { playId: string, roundId: string,
        action: 'keep'|'hide'|'reply'|'ban'|null /* null = timed out */,
        ms: number }
res:  { correct: boolean, bestAction: string, reason: string, isTrap: boolean }
```

Guards: the round must belong to the play; a second answer for the same round returns 409; `ms` is clamped to 200 to 6000; a play that already finished returns 409.

**POST /api/game/finish**

```ts
req:  { playId: string }
res:  { score: number, totalMs: number,
        rank: { key: string, title: string },
        shareUrl: string, ogImageUrl: string }
```

Requires all 10 answers or returns 400. Returns 400 `too_fast` if server time from `started_at` to now is under 8 seconds. Calling it again for a finished play returns the same result. The per-type breakdown is stored but not returned.

**GET /api/game/\[playId\]/breakdown**

```ts
res:  { byType: { type: string, correct: number, total: number }[],
        missed: { body: string, yourAction: string|null,
                  bestAction: string, reason: string }[] }
```

Returns 403 unless the request carries the signed unlock cookie for this `playId`.

**POST /api/lead**

```ts
req:  { playId: string, email: string, firstName?: string,
        role: 'brand'|'agency'|'creator'|'other',
        consent: true, ref?: string,
        website?: string /* honeypot, must be empty */ }
res:  { ok: true, referralUrl: string }
```

Behaviour: if `website` is non-empty, return `{ ok: true }` and store nothing. If the email already exists, return the same success response (no account enumeration), re-send the confirmation email, and set the unlock cookie. On success set the unlock cookie (httpOnly, signed, 30 days) for that `playId`. Ignore `ref` if it equals the new lead's own code.

**GET /api/lead/confirm?token=...**

Sets `confirmed_at`, then redirects to the quiz page with `?confirmed=1`. An invalid token redirects with `?confirmed=0`.

**GET /api/og/\[playId\]**

Returns a 1200x630 PNG (section 8). Unknown or unfinished `playId` returns 404.

## 6. Game rules and scoring

A game is 10 rounds of 6 seconds each, scored out of 10, with total time as the tie-breaker.

**Round composition** (`lib/rounds.ts`): pick 10 active comments per game, then shuffle.

| Type | Count | Correct action |
| --- | --- | --- |
| spam | 2 | hide (ban also accepted) |
| scam\_dm | 2 | ban (hide also accepted) |
| troll | 1 | hide (ban also accepted) |
| complaint (legitimate, angry) | 2 | reply |
| sarcasm (sounds harsh, is friendly) | 1 | keep (reply also accepted) |
| question | 2 | reply |

Every game must include at least 3 rows with `is_trap = true` (complaint, sarcasm, or a question containing a word a keyword filter would block, such as "free"). Never repeat a comment within a game. Prefer comments the visitor has not seen in earlier plays from the same `sessionId`.

**Scoring** (`lib/scoring.ts`, pure functions with unit tests): an answer is correct if `action` equals `best_action` or `alt_action`. A timeout (`action = null`) is wrong and counts as 6000 ms. Score is the number correct; `total_ms` is the sum of clamped `ms`.

**Rank titles**

| Score | Key | Title |
| --- | --- | --- |
| 0 to 3 | rookie | Rookie Moderator |
| 4 to 5 | weekend | Weekend Mod |
| 6 to 7 | cop | Comment Cop |
| 8 to 9 | hammer | Ban Hammer |
| 10 | legend | Ban Hammer Legend |

**Screens and states** (one `useReducer` state machine in `Game`): `idle` then `loading` then `playing` then `revealing` (feedback shown for 1.5 s, tap to skip) then back to `playing` until round 10, then `finishing`, then `result`.

**Feedback per round:** green or red flash plus an icon and text (never colour alone), the correct action, and the one-line `reason`.

**AI reveal (off by default).** On the result screen, if `AI_REVEAL_ENABLED=true`, show a split "You vs Social Kirin AI" using `AI_REVEAL_ACCURACY` and `AI_REVEAL_SECONDS`. Those values must come from running the real classifier over the full seed bank; never hard-code marketing numbers. When disabled, show the line "Now imagine this on 5,000 comments a day." instead.

**Accessibility and input:** keyboard shortcuts K, H, R, B for the four actions; buttons at least 48 px tall; feedback announced through an `aria-live` region; respect `prefers-reduced-motion`; playable with keyboard only.

## 7. Frontend components

Build mobile-first at 375 px width, single column, with the four action buttons fixed in the thumb zone at the bottom of the screen.

| Component | Responsibility |
| --- | --- |
| `Game` (client) | Owns the state machine, calls the three game endpoints, fires analytics events |
| `CommentCard` | Renders one fake comment or DM: handle, avatar placeholder, body, platform label |
| `ActionBar` | Keep, Hide, Reply, Ban buttons with shortcuts K, H, R, B; disabled during feedback |
| `TimerBar` | 6-second countdown bar; on zero it submits `action: null` |
| `FeedbackPanel` | Correct or wrong state, correct action, one-line reason |
| `ResultCard` | Score, rank title, total time, share buttons, AI reveal or fallback line |
| `EmailGate` | Locked breakdown preview plus the lead form (section 9) |
| `BreakdownTable` | Per-type results and the missed rounds, shown after unlock |
| `ReferralBox` | Referral URL, copy button, share buttons |

**Design rules**

- `CommentCard` must use generic styling with the platform name as a text label. Do not copy any real platform's logo, colours or UI, and do not use real people's or brands' names in content.
- Render comment text as plain text. Never use `dangerouslySetInnerHTML`.
- Load the game bundle only after the intro has painted, and keep the page under 200 KB of gzipped JavaScript.
- Persist nothing sensitive in `localStorage`; only `sessionId` and the `ref` value.

## 8. Share card and share text

Every finished play gets a public result page and a 1200x630 image, so a shared link previews as a score card on X, LinkedIn and messaging apps.

- **Result page:** `/tools/spot-the-spam-comment-quiz/r/[playId]` shows the score, title and time, with a "Play it yourself" button. It shows no breakdown and no email. Set `robots: noindex, follow` and a canonical pointing to the main quiz page.
- **Metadata:** `generateMetadata` sets `og:title`, `og:description`, `og:image` (`/api/og/[playId]`) and `twitter:card = summary_large_image`.
- **Image content:** rank title in large type, "8/10 in 52s", one line "Can you beat me?", the Social Kirin wordmark and the short URL. High contrast, readable at thumbnail size, no comment text from the game.
- **Caching:** the image never changes for a given play, so send `Cache-Control: public, max-age=31536000, immutable`.

**Share text templates** (append `?utm_source=share&utm_medium=result`):

- X: `I scored {score}/10 as a comment moderator in {seconds}s and earned the title {title}. Can you beat me? {url}`
- LinkedIn: `I just tried a 60-second comment moderation test: {score}/10, {title}. Try it: {url}`
- Mobile: use the Web Share API when available, otherwise show copy-link and the two links above.

## 9. Email gate, waitlist and referral

Playing and seeing the score are free; the email only unlocks the category breakdown and the referral link.

**Form** (`EmailGate`): email (required), first name (optional, used to personalise the result), role dropdown (Brand, Agency, Creator, Other; required), an unticked consent checkbox with a link to the privacy policy (required), and a hidden honeypot field named `website`. Button text: "Unlock my breakdown".

**Flow**

1. `POST /api/lead` stores the lead with `consent_at`, a random `confirm_token` and an 8-character base32 `referral_code`.
2. The response sets the unlock cookie, so the breakdown appears immediately without waiting for the email.
3. Resend sends one confirmation email with `/api/lead/confirm?token=...`. No marketing email is sent before the lead confirms.
4. Referral link format: `{SITE_URL}/tools/spot-the-spam-comment-quiz?ref={code}`. The page reads `ref` on load and stores it; it is sent with the lead form.
5. A referral counts toward queue position only when the referred lead confirms.

**Copy on the confirmed screen:** show the referral link and the line "Each friend who confirms moves you up the waitlist." Show the actual queue position only after the lead has confirmed.

**Privacy:** store `ip_hash = sha256(ip + IP_HASH_SALT)`, never the raw IP. Do not send emails or names to analytics. The owner should review the consent wording and privacy policy against Malaysia's PDPA and any EU visitors' GDPR requirements before launch; this spec is not legal advice.

## 10. SEO

The quiz page must be crawlable text wrapped around the game, because Google cannot read a JavaScript game. Expect small search volume (US Google Ads data shows roughly 110 monthly searches for "instagram spam comments" and 210 for "instagram scam dm"), so treat SEO as a bonus and social sharing as the main channel.

- **Title (60 characters or fewer):** `Spot the Spam: Free Comment Moderation Quiz | Social Kirin`
- **Meta description (155 characters or fewer):** `Can you tell spam comments and scam DMs from real customers? Take the 60-second quiz, then see how AI moderation handles it.`
- **H1:** "Can you moderate 10 comments before the timer runs out?"
- **Server-rendered sections below the game**, each with an H2: "How the quiz works", "Spam comments and scam DMs to watch for on Instagram", "Why keyword filters hide real customers", "FAQ" (4 to 5 questions), and a waitlist call to action.
- **Target terms, used naturally in headings and body:** primary "instagram spam comments"; secondary "instagram scam dm".
- **Structured data:** `FAQPage` and `BreadcrumbList` JSON-LD. Google now shows FAQ rich results for very few sites, so do not expect a visible benefit; it is harmless.
- **Indexing:** the quiz page is indexable and in `sitemap.xml`; result pages (`/r/[playId]`) are `noindex` and excluded from the sitemap.
- **Performance targets:** LCP under 2.5 s on mobile, no layout shift when the game loads, no images except the OG card.
- **Internal links:** add a link from the home page and a "Free tools" item in the site navigation.

## 11. Analytics and abuse protection

Track eight events so the owner can see where players drop off and which posts drive signups. Every event carries `sessionId` and the stored UTM source.

| Event | Fired when | Extra properties |
| --- | --- | --- |
| `quiz_view` | Quiz page loads | referrer |
| `game_start` | Start tapped | playId |
| `round_answered` | Each answer | roundIndex, correct, ms |
| `game_complete` | Finish returns | score, totalMs, rankKey |
| `gate_view` | Email gate becomes visible | score |
| `lead_submit` | Lead API returns success | role, hasRef |
| `lead_confirm` | Confirmation link opened | none |
| `share_click` | A share button is used | channel |

Never send emails, names or comment text to analytics.

**Abuse limits** (Upstash, keyed by hashed IP unless noted):

| Route | Limit |
| --- | --- |
| `/api/game/start` | 20 per hour |
| `/api/game/answer` | 60 per minute per `playId` |
| `/api/lead` | 5 per hour |

**Other guards**

- Reject a `finish` call if server time since `started_at` is under 8 seconds.
- Reject duplicate answers for a round and any answer after `finish`.
- Same-origin only for all routes; no CORS headers.
- Reject known disposable-email domains with a small static list in `lib/`.
- If lead spam appears, enable Cloudflare Turnstile on the form using `TURNSTILE_SECRET`.
- Keep the service-role key out of any client bundle; add a test that greps the built client code for it.

## 12. Seed data

The game needs at least 40 comments in `data/comments.json` before launch, and `scripts/seed.ts` must upsert them idempotently (match on `platform + author_handle + body`).

**Minimum bank:** 8 spam, 8 scam\_dm, 5 troll, 8 complaint, 5 sarcasm, 6 question, with at least 12 rows marked `is_trap: true`.

**Content rules**

- Invent every handle. No real brands, people, phone numbers or working links; use `example.invalid` for any URL.
- Each `reason` is one sentence, plain words, and says why the action is right (for example, that real platforms never DM appeal links).
- Mix difficulty: about 40% level 1 (obvious), 40% level 2, 20% level 3.
- Comments must read like real ones: typos, emoji and slang are fine; no slurs or graphic content.

## 13. Build order and acceptance criteria

Build in this order, and do not start a step until the previous step's checks pass.

1. Scaffold the app, env validation and Tailwind; deploy an empty page to a Vercel preview.
2. Run the migration, write `data/comments.json` (at least the 6 sample rows) and `scripts/seed.ts`.
3. Implement `lib/rounds.ts`, `lib/scoring.ts` and the three game routes, with Vitest tests.
4. Build the `Game` state machine and components against those routes.
5. Build the result page and the OG image route.
6. Build the lead route, unlock cookie, breakdown route and confirmation email.
7. Add the SEO copy, metadata, JSON-LD and sitemap.
8. Add analytics events and rate limits.
9. Run the full checklist below and fix failures.

**Acceptance checklist**

- [ ] `/api/game/start` response contains no `best_action`, `alt_action`, `reason`, `type` or `is_trap` field.
- [ ] A second answer for the same round returns 409; `finish` called twice returns the same result.
- [ ] `finish` returns 400 `too_fast` when called under 8 seconds after `start`.
- [ ] Scoring tests cover correct, alternate-correct, wrong and timeout answers, and the tie-break.
- [ ] Every generated game has exactly the composition in section 6 and at least 3 trap rounds.
- [ ] `/api/game/[playId]/breakdown` returns 403 without the unlock cookie and 200 with it.
- [ ] A lead submitted with the honeypot filled returns success but creates no row.
- [ ] A duplicate email returns the same response as a new one and re-sends the confirmation.
- [ ] The service-role key does not appear in any client bundle.
- [ ] The game is fully playable with the keyboard alone and at 375 px width with no horizontal scroll.
- [ ] Result pages are `noindex`; the quiz page is indexable and listed in the sitemap.
- [ ] `/api/og/[playId]` returns a PNG in under 2 seconds for a valid play and 404 for an invalid one.
- [ ] Lighthouse mobile on the quiz page: Performance 90 or higher, Accessibility 95 or higher, SEO 100.
- [ ] With `AI_REVEAL_ENABLED=false`, no AI accuracy or speed claim appears anywhere in the UI.

**Decisions the owner must make before launch:** whether to enable the AI reveal (needs measured numbers), the waitlist queue formula in section 4, and the privacy policy and consent wording.
